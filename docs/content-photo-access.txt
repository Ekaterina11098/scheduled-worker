Detailed request/file identifiers and evidence remain in the private technical cache, not this public document.

Scope: existing China-cabinet product cards, source photographs only. No product, inventory, pricing, catalog or other business writes. No image-generation calls. The owner's Google API exception covers only the dedicated photo folder; other paused integrations remain paused.

Required session capabilities: authorized Supabase execute_sql for the configured project, connected Google Drive raw-file import, and a working file/image environment. Repository read access alone is insufficient. These connectors must be available to the employee's actual account/session.

For a NEW explicit task, request either exact article codes OR one family:
select public.content_photo_request(p_articles=>array['EXACT_ARTICLE'],p_max_photos=>24);
OR select public.content_photo_request(p_family=>'MODEL_FAMILY',p_max_photos=>24);
The family is the second hyphen-separated article token, case-insensitive. Choose only one selector. Use a few photos per card for color galleries; request the necessary views for full product slides.

Save request_id and poll:
select public.content_photo_result('REQUEST_UUID'::uuid);
queued/running means wait for the SAME request; do not create duplicates. The dedicated recovery clock dispatches the worker automatically when queued work exists. Employees do not click GitHub Actions or ask the owner to forward archives.

On ready, use drive.file_id or drive.url with the connected Google Drive tool: read metadata, then fetch raw file with download_raw_file=true and include_base64=false. Import the returned file resource into the working environment. Verify archive_bytes/archive_sha256, unpack ZIP, read MANIFEST.json for article/nmID/file mapping, and open actual image pixels before designing. A ready result or URL is not sufficient proof. Do not use the old direct CDN/signed-object download path in place of the verified Drive import.

On failed, inspect safe_error and request_id. Permit one justified retry of a transient transport error, not an endless loop. Report timed_out or a missing session connector precisely. Never request, print or publish tokens. Existing exported Drive files are private and do not use the old one-hour signed-object link. Owner revocation, storage limits or a connector outage can still interrupt access.

Limits: 60 cards; 24 photos/card; 600 photos; 100 MiB source bytes/request; 20 requests/day. Split larger selections by exact article lists. New bags without a China card require employee-provided source photos. The worker does not invent product details.

Server: dedicated content-photo-bridge.yml and content-photo-clock; private request cache; fixed owner-selected Drive folder; only drive.file OAuth scope. Credentials are in a restricted server vault. Uploads are private, resumable and idempotent by request UUID, with metadata, size, MD5 and authenticated SHA-256 readback. No public artifacts or sharing-permission calls. Drive archives remain until owner deletion; the old seven-day Supabase cleanup rule does NOT delete Drive files.
